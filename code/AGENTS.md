# Agent 工作偏好（用户指示）

- 本仓库（Heston 模型校准与模拟）中的代码和文档允许自由访问和修改，本文件除外。
- 虚拟环境使用data_process，代码和文档文件编码均为UTF-8。
- 文档文件统一存放在与code同级的文件夹下，使用MKdocs创建和维护。
- 不存在的文档和代码文件请按照本文件要求新建，命名风格和项目一致、清晰。
- py代码必须使用typehint，并为函数和类等编写docstring。在docstring变更后，使用MKdocs生成API文档。
- 在项目summary_proj.md文档中详尽写明了每个文件的职能、模块依赖、数据流向、算法选择和设计思想。
- 类的构成、函数的输入输出和主要作用、变量的类型等等，请在API文档当中查阅。
- 以软件工程的要求来为项目生成所需要的详尽的流程图、数据流图等辅助md（若你认为需要）。
- 如果项目当中存在已构建文档文件，请先从文档当中理解项目的总体结构和封装，在你认为需要时，再去查看源代码结构。
- 更新后，如逻辑代码改变，请编写(或调用已有的)测试用例测试（测试用例统一使用 pytest 框架，测试文件置于tests/目录下，命名规则为test_<模块名>.py）。如果测试用例失败，则禁止推送，从调用栈等分析测试用例设计、变更逻辑是否合理(如你认为有帮助，使用help查阅依赖函数或类等的文档或联网检索)。随后再次测试，测试失败超过7次，执行git reset --hard HEAD  和git clean -fd随后终止本次开发任务。
- 测试通过后，若此次公共接口发生变更、项目使用的算法和依赖改变（或增加），在项目下的progress.md下记录更新和项目进展(微小的代码格式调整（如空格、注释）无需记录)同时更新其他文档，编辑commit message并将更新推送到本地git仓库。
